Architectural Scenarios Deep Dive

Technical implementation details, mechanics, and operational steps for each migration pattern.

Pattern 2

Filesystem Streaming (pv-migrate / rsync)

Establishes a direct POSIX data streaming pipeline between ephemeral reader and writer pods mounted to the source and target PVCs. Preserves Unix UID 999:ping permissions, metadata, and timestamps over an authenticated channel.

Transfer Speed: 47.3 MB in 0.98s
Total Cutover: 9.37 seconds
Best For: Fast Direct Migration
# Stream POSIX pipe
$ kubectl exec src -- tar -cf - pgdata | kubectl exec -i dest -- tar -xpf -
Replication completed in 0.985s
Pattern 3

Velero + MinIO S3 Object Store

Leverages Velero v1.14.1 with Kopia pod volume backup engine to capture complete application metadata (CRDs, Helm release secrets, ConfigMaps, Secrets, NetworkPolicies) and volume data into an S3 bucket at https://10.163.44.130:9000.

Backup Duration: 3.97 seconds (52 items)
Restore Duration: 9.04 seconds (20 items)
Best For: Cross-DC / DR / Air-Gap
# Velero Restore
$ velero restore create --from-backup payments-db-v1 --namespace-mappings migration-demo:demo-velero --wait
Completed in 9.04s
Pattern 1

Zero-Copy FCD / CNS Adoption

Capitalizes on shared VMware vSAN ESA block storage. When the source PVC is deleted with reclaimPolicy Retain, the physical First Class Disk (FCD) is cleanly detached from the worker node VM without deleting the volume. Target cluster statically binds the FCD via Paravirtual CSI with zero network copy.

Network Transferred: 0 Bytes
Total Cutover: 17.49 seconds
Best For: Multi-TB Large Databases
